# Resource Quality & Maintenance

This repository lists third-party resources. A link is **not** an endorsement, proof of safety, or authorization to access another party's systems.

## Inclusion standards

Contributors should provide a canonical URL, an identifiable OSINT use case, category, last-manually-checked date, and any known login, payment, API-key, geographical, or coverage restrictions. Prefer official sources over clones. Avoid credential dumps, stolen data, doxxing, malware downloads, and unauthorized-access services.

## Status terms

| Status | Meaning |
| --- | --- |
| Verified (dated) | Page and described purpose manually checked on the recorded date |
| Access restricted | A login, payment, API key, or geographical restriction applies |
| Redirected / changed | Destination or capabilities changed; needs manual review |
| Intermittent | Bot blocking, rate limiting, or transient errors; not automatically dead |
| Deprecated | Publisher documents retirement or archival |
| Unverified | No recent manual check recorded |

Legacy links without dated verification notes should be treated as **unverified**.

## Automation vs. judgment

The local documentation checker validates internal Markdown links and headings. It intentionally **does not** validate external URLs. External URL audits, when enabled, provide leads for human review only; HTTP errors, rate limits, and crawler blocks are not definitive evidence that a product is gone.

A maintainer should manually confirm a broken link, investigate redirects, avoid unrelated replacement sites, and update the entry. Never publish secrets or unredacted personal research evidence in issues or pull requests.
